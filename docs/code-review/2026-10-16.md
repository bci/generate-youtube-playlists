## Fixed

Each fix is a separate, small diff. The bug fixes followed CLAUDE.md section 5: the test was
written first and watched fail on the old code, then passed after the fix.

1. **Writes retried on permanent 4xx errors.** `src/youtube.js:120` (new `isPermanentError`),
   `:956`, `:974` and `:1068`.
   - *What:* `withRetry` around `playlistItems.delete`, `videos.rate` and
     `playlistItems.insert` treated only quota errors (and, for inserts, manual-sort refusals)
     as fatal. A 400 or 404 was retried 4 more times, with 1+2+3+4 seconds of backoff.
   - *Why:* CLAUDE.md section 11 says "Quota errors and permanent 400s are declared fatal on
     purpose: retrying them burns 50 units per attempt and cannot succeed." The code did not
     match. The final outcome is unchanged: the error is still thrown, and the channel is
     still reported as failed. Only the wasted attempts are gone.
   - *Scope, on purpose:* only 400 and 404. 403 carries the quota reasons, which
     `isQuotaError` already handles. 409 is sometimes transient on concurrent playlist
     edits, so it is still retried.
   - *Verified by:*
     - `test/prune.test.js:400`. A 404 on delete gives one attempt. Before the fix: 5
       attempts and 10 s.
     - `test/youtube.test.js:228`. A 404 on insert gives one attempt.
     - `test/youtube.test.js:244` tests the classifier itself.
2. **`setEnvValue` corrupted a value containing `$`.** `make.js:446`.
   - *What:* `content.replace(re, \`${key}=${value}\`)` reads `$&`, `$1` and `$'` in the
     replacement string as patterns. So `make change-email` given `a$&b@example.com` wrote
     the matched line back into the address.
   - *Fix:* a replacer function.
   - *Verified by:* `test/make.test.js:198`.
3. **The secret scan could not see a file with a non-ASCII name.** `checks.js:112-113`.
   - *What:* without `-z`, `git ls-files` quotes such paths (`"test/\303\274.txt"`). The
     quoted form names no file, so `trackedFiles()` skipped it without saying so. Every
     check missed that file, including the CLAUDE.md section 12 public-repo scan.
   - *Reproduced:* an untracked file with a planted address and an accented name gave
     `false 0` (not listed, no finding).
   - *Fix:* NUL-separated output.
   - *Verified by:* `test/checks.test.js:277`. The count of tracked files is unchanged at 57.
4. **The OAuth temp file holding the client secret was created world-readable.**
   `src/auth.js:127`.
   - *What:* `runAuthFlow` writes the client id and secret to `os.tmpdir()` with the
     default mode. On macOS that directory is per-user. On Linux it is the shared `/tmp`,
     with mode 0644 after the usual umask.
   - *Fix:* `{ mode: 0o600 }`. It has no effect on Windows.
   - *Not unit-tested:* the function opens a browser for a real Google sign-in. That is
     interactive by design and not mockable without restructuring the module. Verified by
     reading the code and by lint and tests.

## Found, not fixed

- **Ledger file names can collide.** `src/seen.js` `ledgerFileName` collapses every run of
  characters outside `[A-Za-z0-9._-]` to `_`. So `A B` and `A_B` share a ledger. On a
  case-insensitive filesystem (the macOS and Windows defaults), `Foo` and `foo` also share
  one. This is unlikely with handle-derived titles. Fixing it changes the on-disk format,
  which is a data-format change.
- **`src/auth.js` `upsertEnv` has the same `$`-in-replacement shape as fix 2.** It is left
  alone because the only value it ever writes is a Google refresh token, whose character
  set (`1//` plus base64url characters) contains no `$`.
- **Heartbeat fields are not HTML-escaped** in `buildAlertHtml` (`src/heartbeat.js`), and
  `check.reason` can echo a malformed `finishedAt`. The source is our own
  `state/last-run.json`, so the risk is negligible.
- **The report footnote** (`src/report.js`, "Removed videos are ones you liked or saved…")
  leaves out the other two reasons a video is deleted: it was removed by hand, or it falls
  below an `after=` cutoff. This is wording; the decision is Kent's.
- **`.gitignore` lists `.agent-pipe/` twice**, each with its own comment. This is harmless.
- **`make.js` `main().catch`** has two branches that do the same thing (the `Fail` branch
  and the plain-`Error` branch). This is harmless, and the comment explains the plain one.
- **`make logs -5` or `make logs 0`**: `parseInt(...) || 40` turns 0 into 40, and a
  negative count slices from the start of the file. This is cosmetic.

## Questions for Kent

1. **`.claude/launch.json` runs a full live sync.** Its only configuration is
   `npm run start` on port 3000. This tool has no server, so the port is meaningless.
   `npm start` with no arguments syncs every channel in `channels.txt` for real. Any Claude
   session that calls `preview_start` on it spends real quota and edits the account.
   **Recommendation:** delete the file. If a launcher is wanted, point it at
   `node make.js dry-run`, with no port.
2. **Unparseable caps fail open.** `--max=abc` and `--max-removals=abc` print a warning and
   then mean *unlimited* (`parseLimit` in `src/index.js`). `test/prune.test.js` pins this
   behaviour on purpose. Every other malformed setting (`after=`, `older=`, `shorts=`) is
   fatal, for exactly the reason that applies here: the safety flag silently disappears.
   **Recommendation:** make an unparseable limit fatal, and update that test.
3. **`make --no-print-directory <target>` is refused** with "make consumed --dry-run".
   - *Why:* `eatenMakeFlags` treats the first word of `MAKEFLAGS` as option letters. With
     only long options, that word is `--no-print-directory`, which contains an `n`. Any
     long-only make option does the same (for example `--warn-undefined-variables`).
     Reproduced with GNU Make 3.81.
   - It fails closed, so it is safe, only annoying.
   - **Recommendation:** skip a first word that starts with `--`. Before that, confirm how
     GNU make 4.x writes `-l` into `MAKEFLAGS`. Only 3.81 is installed here, and I did not
     want to risk weakening the `--max` guard.
4. **`--email` with only `ERROR_ALERT_TO` set mails `undefined`.**
   - *Why:* the recipient guard in `main()` is `!REPORT_TO && !ERROR_ALERT_TO`. Since
     `ERROR_ALERT_TO` falls back to `REPORT_TO`, that is just `!ERROR_ALERT_TO`. With
     `REPORT_TO` unset, the report send goes to `undefined` and fails at Graph. The exit
     code is still 1, but the message is unclear.
   - **Recommendation:** check each send's own recipient. `main()` is not exported, so a
     test needs a small refactor first.
5. **`shorts=split shorts-title=<the channel's own name>`** makes both targets the same
   playlist. Videos and Shorts are then diffed, inserted and pruned against one playlist,
   and one ledger file is written twice. Nothing rejects the line.
   **Recommendation:** reject a split whose two titles match case-insensitively. Do it in
   `main()` after resolution, because the default name is only known then.
6. **CLAUDE.md has two "section 11"s.** The core block's "Documentation and Readable Code"
   and the repo's "This Tool Spends Quota" share the number. Code comments say "CLAUDE.md
   section 11" meaning the quota rules.
   **Recommendation:** renumber the repo sections 12 to 15, and update the handful of
   comments that cite them. Your call, since CLAUDE.md is the rulebook.
7. **`npm audit`: 1 high and 3 moderate, all transitive.** They are brace-expansion; qs;
   uuid, directly and through gaxios.
   **Recommendation:** run `npm audit fix` in its own change, then run the full test suite
   and a `dry-run`. This review did not change dependencies.
8. **A Shorts probe that errors files the Short as a video for good.**
   - *Why:* `isShortByUrl` returns false on a network error or timeout, by design ("don't
     drop the video"). The Short is then inserted into the *videos* playlist. When a later
     run classifies it correctly, nothing removes it, because only watched and below-cutoff
     videos are deleted.
   - **Recommendation:** accept and document it, or treat a probe error as "unknown" and
     leave that video out of both playlists for this run.
9. **A delete whose first attempt succeeded but whose reply was lost** is retried and gets
   404. That marks the channel failed for the night. Fix 1 did not change this outcome; it
   now fails 10 s sooner.
   **Recommendation:** treat 404 on `playlistItems.delete` as "already gone", meaning
   success. That is a behaviour change, so it is your call.
10. **The `.cmd` wrappers end without `exit /b %ERRORLEVEL%`.** The Task Scheduler's
    LastTaskResult (which the watchdog email tells the reader to check) relies on the
    final `echo` leaving node's ERRORLEVEL untouched. I believe it does, but I could not
    verify that on Windows from here.
    **Recommendation:** add an explicit `exit /b` with the saved status, the way the `.sh`
    wrappers do.
